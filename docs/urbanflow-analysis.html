What this actually is

UrbanFlow is a single-laptop Spark pipeline over NYC taxi trip records — not a cluster system. It runs Spark in local mode: one JVM process standing in for both driver and executor. There is no HDFS, no YARN, no Cassandra, no cluster to provision, by design — the project brief in CLAUDE.md is written around "three people, six weeks, 8 GB laptops."

The pipeline

Six stages, bronze to dashboard. Nothing here needs a network service beyond the initial TLC download — every arrow after ingest is a local file read.

Input in, outcome out

What a user actually provides, and what comes back.

User input

  • A tier choice — make synth (no download) or make ingest TIER=0|1|2 for 1/24/12 months of real TLC files
  • Nothing else. No forms, no uploads — the whole run is driven by make targets
  • Interactive filtering happens later, inside the dashboard: borough, hour, weekday/weekend, card vs cash

Outcome produced

  • quality_report.json — rows dropped, per cleaning rule
  • data/gold/* — six tables: speed-by-hour, demand curves, airport trips, tip bias, and more
  • model_results.json — trip-duration model vs a naive baseline
  • benchmarks.json — Parquet vs CSV, broadcast vs sort-merge join, core scaling
  • A live dashboard at localhost:8501 rendering all of the above

Platform: what it needs, what it doesn't

No Cassandra, no Hadoop/HDFS, no YARN. The repo is explicit that the entire point is fitting real distributed-processing concepts onto one machine.

ComponentNeeded?Why
Apache Spark (local mode)YesAlready the engine — session.py starts one JVM, no cluster manager attached
Java 17 / 21 / 25YesSpark 4.2 refuses to start on Java 8 or 11 — check first with java -version
DuckDB + StreamlitYesServes the dashboard from gold-layer files only, no live Spark
Hadoop / HDFS / YARNNoBronze is just local files under data/raw/; nothing here is cluster-distributed
Cassandra / any database serverNoEvery layer (bronze/silver/gold) is Parquet/JSON on disk, read by DuckDB — no server process to run
GPUNoDuration model is a baseline comparison, not deep learning

Codespaces, specifically

Will work

  • Only real requirements are Java 17+ and Python 3.10+ — both installable in any Codespace with apt/pyenv, no container orchestration needed
  • make setup → make check → make synth → make dash needs no network beyond package installs — the default 4-core/16GB machine type covers Tier 0/1 comfortably
  • Streamlit's port forwards automatically in Codespaces, so localhost:8501 becomes a shareable preview URL
  • Public repo is safe as-is: data/, *.parquet, *.csv are already gitignored, so no multi-GB taxi data or generated artifacts ever get committed

Worth adding first

  • No .devcontainer/ exists yet — without it, whoever opens the Codespace has to run scripts/doctor.sh/make check manually each time to confirm Java before anything else
  • Tier 2 (230M rows, 5.8 GB) is the one run worth doing on a beefier machine type — the brief itself says run it once, in week 4, not routinely
  • make ingest pulls from TLC's public S3 bucket — fine on Codespaces' network, just budget the download minutes
