Duration Model, Explained

What actually flows into the model, what algorithm it runs, and how it gets graded — with the terms corrected along the way.

First, the terms that don't apply here

Three names came up that belong to a different kind of model. Worth being precise about, since they'd point you at the wrong mental model entirely.

TermUsed here?What it actually is
Grad-CAMNoHighlights which pixels a CNN looked at, for image classifiers. There are no images and no neural network anywhere in this pipeline.
Sigmoid / logistic regressionNoSquashes an output into a 0–1 probability, for yes/no classification. We're predicting a continuous number (minutes), not a category — nothing here gets squashed to a probability.
StackingNoTrains several different model types, then a meta-model learns how to blend their outputs. Diagrammed below, for contrast.
Gradient boostingYesOne model type (decision trees), trained one at a time, each new tree correcting the previous ensemble's mistakes. This is what GBTRegressor actually does.

Boosting, not stacking — what's actually inside GBTRegressor

These are genuinely different techniques, not two names for the same thing. Drawing the real difference:

✓ Boosting — what we're using

One decision tree at a time. Each new tree's only job is to predict what the previous trees got wrong. The final prediction is the sum of all 30 trees' corrections.

✗ Stacking — not used here

Several different model families trained independently and in parallel, then a separate model learns how to weigh their outputs. Nothing in this project does this.

Grading it — the testing/evaluation flow

A model score alone means nothing without something honest to compare it against — that's the whole reason the baseline exists.

What the three metrics actually mean

MetricIn plain terms
RMSE (root mean squared error)Typical prediction error in minutes — but big misses count extra (squared before averaging), so it punishes the model for being wildly wrong on a few trips more than MAE does.
MAE (mean absolute error)Average error in minutes, treating every miss equally. Easier to say out loud in the report: "off by X minutes on average."
R²Fraction of the variation in trip duration the model explains — 1.0 would be perfect, 0.0 would be "no better than always guessing the average."

Plus feature importance from the trained trees — which of trip_distance, pickup_hour, pickup_dow, pu_borough, do_borough the 30 trees actually relied on. That answers "what are the key factors" directly, once training finishes.
