What actually broke

Both were real bugs in the project's own reference code — not caused by Docker, memory, or bad luck. Both are fixed and verified before letting the run continue.

Fixed · session.py

Bug #1 — every month except the last one was silently erased

Spark's default write mode overwrites the entire output folder, not just the partition being written. curate_month() writes one month at a time into a year=/month= folder tree with mode("overwrite") — so month 2's write deleted month 1, month 3 deleted month 2, and so on. Only December survived. This silently breaks any multi-month tier, including Tier 1's 24 months, not just Tier 2.

Fixed by setting spark.sql.sources.partitionOverwriteMode = dynamic once, in session.py — the single place every Spark session in this project is created.

Fixed · analyze/model.py

Bug #2 — the model saw zero training rows

FHVHV (Uber/Lyft) trips have no passenger_count field at all — it's genuinely absent, not just sometimes missing, so every row has it as null. model.py hard-coded passenger_count as a training feature and then called .dropna(), which discards a row if any selected column is null. Every single row qualified, so training and test sets both came out empty.

Fixed by dropping passenger_count from the feature list specifically for fhvhv/fhv, instead of inventing a fake value for a field that honestly doesn't exist in the source data.
